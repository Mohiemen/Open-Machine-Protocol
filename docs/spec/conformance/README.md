# Conformance Vectors

| | |
|---|---|
| **Status** | v0.1 initial set |
| **Location** | spec/conformance/ |
| **Authority** | Core Schema Specification section 8: "Conformance vectors in spec/conformance/ are the executable definition of this section. An implementation that passes all vectors is conformant for the covered behavior." |

## Layout

```
spec/conformance/
├── core/
│   ├── valid.ndjson       # envelopes a conformant validator MUST accept
│   ├── invalid.ndjson     # cases a conformant validator MUST reject
│   └── cases.md           # what each vector tests and why
├── consumer/
│   └── cases.md           # consumer-behavior cases (suites follow with the
│                          #   reference consumer, roadmap M2)
└── tools/
    └── gen_vectors.py     # regenerates the NDJSON with correct checksums

spec/profiles/{name}/conformance/   # per-profile valid/invalid vectors
```

## Runner Semantics

- **valid.ndjson** - one envelope per line. A conformant validator accepts
  every line against the envelope schema, the named body schema, and the
  declared profile's constraints, and verifies every checksum successfully.
- **invalid.ndjson** - one object per line of the form
  `{"_reason": "...", "vector": {...}}`. A conformant validator rejects each
  `vector`; `_reason` documents the intended failure (a rejection for a
  different additional reason still passes the vector, but implementers should
  investigate mismatches).
- Signature (`sig`) vectors are checked for syntactic validity only - signature
  *verification* depends on key material and is exercised in gateway/consumer
  test suites, not static vectors.

## Checksums

Every vector's `checksum` is real: SHA-256 over the RFC 8785 (JCS) canonical
serialization of `body`, generated by `tools/gen_vectors.py`. Vector bodies
deliberately avoid non-integer numbers so that a plain sorted-key compact JSON
serialization is JCS-equivalent; if you add vectors with floats, switch the
generator to a full JCS implementation first. Never hand-edit the NDJSON -
edit the generator and re-run it.

## Claiming Conformance

Per spec section 8.5: an implementation that passes all vectors may claim
conformance *for the covered behavior*. The vectors do not cover everything
(sequence persistence across restarts, dead-letter behavior, interval-overlap
rules across messages are runtime behaviors) - those are validated in the
gateway's own test suite and, for consumers, the cases in `consumer/cases.md`.
